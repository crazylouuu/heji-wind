## 1. 可访问性

### 发现并修复的 6 处对比度问题

用脚本遍历所有可见文字，按 WCAG AA（普通文字 4.5:1、大字号 3:1）计算：

| 元素 | 颜色组合 | 原对比度 | 修复 |
| --- | --- | --- | --- |
| 侧栏分组标题（工作台/工具/实验/设置） | `#999999` on `#ffffff` | 2.85:1 | `--text-light` → `#6b6b6b`（5.33:1） |
| 页面底部提示 | `#999999` on `#f5f5f5` | 2.61:1 | 同上（4.89:1） |
| 导航选中项 | `#1677ff` on `#e6f4ff` | 3.66:1 | 新增 `--primary-on-soft: #0958d9`（5.50:1） |
| 合迹侧栏选中项 | 同上 | 3.66:1 | 同上 |
| 合迹 Tab 选中（白底） | `#1677ff` on `#ffffff` | 4.10:1 | 同上（6.16:1） |
| 主按钮白字 | `#ffffff` on `#1677ff` | 4.10:1 | 新增 `--primary-solid: #0f62d6`（5.62:1） |

> 深色模式已于 2026-10-27 按需求移除（电脑端不需要），
> 原深色主题下的 2 处不达标（三级文字 3.89:1、主按钮白字 2.99:1）随之消失。

### 根因与解法

问题不是"颜色选错了"，而是**把品牌色当成了万能色**。
`#1677ff`（Ant Design 蓝）作为背景和图标没问题，但作为文字色或白字的底色都只有 4.10:1。

解法是把一个主色拆成三个用途明确的 token：

```
--primary         图标描边 / 边框 / focus 环（非文字，3:1 标准）
--primary-on-soft 浅主色底上的文字
--primary-solid   实心背景 + 白字（按钮）
```

一共替换了 18 处 `background: var(--primary)` → `var(--primary-solid)`。

## 复现方式

审计脚本在 `/tmp/audit_1.js`（临时文件，逻辑见下方）。核心做法：

1. 遍历所有含文本节点的可见元素，取 `color` 与实际背景色（向上找第一个非透明背景）。
2. 用 WCAG 公式算对比度：`(L1+0.05)/(L2+0.05)`。
3. 按字号判断阈值：≥24px 或 ≥18.66px 且 700 字重用 3:1，其余 4.5:1。
4. 同时检查触控目标尺寸、图片 alt、表单标签、标题层级、横向滚动。

如果要长期用，建议把它固化成 `scripts/ui-audit.js` 并加进构建检查。
