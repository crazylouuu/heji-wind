# ChemELN 安全加固说明（P0.5）

> 日期：2026-10-22 ｜ 影响版本：v1.2.1-free 之后的全部构建
> 目的：收敛单机应用的网络暴露面，为「三应用整合」打前提

---

## 一、发现的问题

2026-10-22 三应用整合调研时扫描 D 盘，发现 chemELN 后端存在一处**长期存在的安全缺陷**：

```python
# backend/main.py（加固前）
uvicorn.run(app, host="0.0.0.0", port=PORT)   # ← 监听所有网卡
```

叠加两个放大因素：

| 因素 | 状态 | 影响 |
| --- | --- | --- |
| 40+ 个 API 路由**无任何鉴权** | 无 `Depends` / `api_key` / `token` | 任何人可直接读写全部数据 |
| `CORS_ORIGINS = ["*"]` | 完全放开 | 任意网页可发起跨源请求 |

**实际风险**：绑定 `0.0.0.0` 意味着**同一局域网内任何设备**都能访问本机 API：

```bash
# 攻击者在局域网任意一台机器上执行：
curl http://<受害者IP>:8765/api/experiments          # 读走全部实验记录
curl http://<受害者IP>:8765/api/compounds            # 读走全部化合物库
curl -X DELETE http://<受害者IP>:8765/api/experiments/1   # 删除数据
```

> **重要澄清**：CORS 只约束**浏览器**的跨源策略，对 `curl` / 脚本 / 其它机器的直连请求
> **没有任何保护作用**。所以「CORS 放开」≠「本地安全」——这是很多人的认知盲区。

黄河化学版（v0.1.3）同样是 `0.0.0.0` + 无鉴权，一并说明。

## 二、修复方案（四层防护）

### 层 1：绑定回环地址（主防线）

```python
# backend/config.py
BIND_HOST = "127.0.0.1"
```

```python
# backend/main.py
_probe.bind((BIND_HOST, PORT))          # 端口探测也改回环
uvicorn.run(app, host=BIND_HOST, port=PORT)
```

局域网**根本连不上**，这是最有效的一层。

### 层 2：会话令牌

新增 `backend/utils/security.py`：

- 启动期生成 32 字节随机 token（`secrets.token_urlsafe(32)`）
- 落盘到 `data_dir()/.session_token`（POSIX 下 0600）
- **优先级**：环境变量 `CHEMELN_TOKEN` > 已存在的 token 文件 > 新生成
  （文件持久化是为了重启后浏览器标签页不失效；环境变量供 Tauri 主壳注入）

**API 请求必须携带令牌**，三种来源任一有效：

| 方式 | Header/位置 | 适用场景 |
| --- | --- | --- |
| Header | `X-ChemELN-Token: <token>` | 脚本、Tauri 主壳、前端显式携带 |
| Cookie | `chemeln_token=<token>` | 浏览器（HttpOnly，自动携带） |
| Query | `?token=<token>` | 极少用（便于手工调试） |

### 层 3：回环地址白名单（纵深防御）

即使有人日后误改回 `0.0.0.0`，中间件也会检查 `scope["client"][0]`：
非回环来源一律 **403**。

```python
def is_loopback(host: str) -> bool:
    if h.startswith("::ffff:"): h = h[len("::ffff:"):]   # IPv4-mapped IPv6
    if h in ("127.0.0.1", "::1", "localhost"): return True
    return h.startswith("127.")                              # 整个 127.0.0.0/8
```

### 层 4：CORS 收口

```python
CORS_ORIGINS = [
    "http://127.0.0.1", "http://localhost",
    "http://tauri.localhost", "tauri://localhost",
]
```

## 三、顺带修掉的路径穿越

审计过程中发现 `spa_catch` 存在**目录穿越**：

```python
# 加固前
file_path = os.path.join(FRONTEND_DIR, full_path)   # 不规范化 ".."
if os.path.isfile(file_path): return FileResponse(file_path)
```

实测 `GET /../backend/config.py` 可读出 `frontend/` 之外的文件
（已验证 `os.path.isfile()` 对含 `..` 的拼接路径返回 True）。

**修复**：先 `normpath` 再校验前缀，越界一律当作不存在：

```python
file_path = os.path.normpath(os.path.join(FRONTEND_DIR, full_path))
frontend_root = os.path.normpath(FRONTEND_DIR)
if not (file_path == frontend_root or file_path.startswith(frontend_root + os.sep)):
    file_path = ""
```

> 审计了其余文件操作点，**均已有 `os.path.basename` 防护**，无需改动：
> - `routers/experiments.py:511,546` — 附件上传文件名
> - `utils/auto_backup.py:228` — `find_backup()` 备份文件定位
> - `routers/data.py` — 导出文件路径由服务端生成

## 四、令牌如何流通（重要）

```
浏览器流程
─────────────────────────────────────────────────────
1. 用户打开 http://127.0.0.1:8765/
2. 中间件：路径 "/" 不在受保护前缀 → 放行
3. 响应是 text/html → 中间件追加 Set-Cookie: chemeln_token=...; HttpOnly; SameSite=Lax
4. 浏览器存下 cookie
5. 前端 fetch('/api/experiments') → 同源 → 浏览器自动带 cookie → 通过

前端主动引导流程（脚本 / Tauri 子 webview）
─────────────────────────────────────────────────────
1. api.js 首次请求前调 GET /api/session（免鉴权，返回 token）
2. 缓存到 API._token
3. 之后每个请求带 X-ChemELN-Token 头
```

### 为什么 Cookie 用 `SameSite=Lax` 而不是 `Strict`

- `Strict` 会阻断「从 `tauri://` 主壳跳转到 `http://127.0.0.1:8765`」这类跨站导航，
  导致 Tauri 子 webview 拿不到 cookie；
- `Lax` 仍允许顶级导航携带 cookie，同时阻断跨站 POST（即 CSRF 的主要攻击面），
  是这里正确的平衡点。

## 六、兼容性影响

| 场景 | 影响 | 说明 |
| --- | --- | --- |
| 浏览器正常使用 | ✅ 无感 | cookie 自动携带 |
| Tauri 子 webview | ✅ 支持 | header 方式，走 `/api/session` 引导 |
| 脚本 / curl 调试 | ⚠️ 需带令牌 | `curl -H "X-ChemELN-Token: $(cat data/.session_token)"` |
| 旧版前端（浏览器缓存） | ⚠️ 需清缓存 | api.js 版本号已 bump 到 v=12 |
| 局域网其它设备访问 | ❌ **已禁止** | 这是**预期的行为变更** |

> 黄河化学版 v0.1.3 仍保持原样（已停更，不再维护）；
> 若需修复，套用同样的四层防护即可。

## 七、给整合方案的收益

1. **子 webview 方案的前提** —— Tauri 子 webview 加载 `http://127.0.0.1:8765`，
   绑回环后不会与其它服务冲突，也不会被局域网访问；
2. **统一数据层的前提** —— 后端能安全地被 Tauri 主壳直接调用（`/api/session` + header）；
3. **「单机应用」名副其实** —— 用户装到公司电脑时，不再担心同网段同事能翻到实验记录。
