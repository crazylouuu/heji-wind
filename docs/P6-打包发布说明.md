# P6 打包发布：Python sidecar + NSIS 单一安装包

> 阶段：P6　｜　状态：已完成
> 目标：把「工具箱 + ChemELN 后端」打成一个安装包，用户机器上**不需要装 Python**。

## 打包架构

```
安装后目录
Program Files\合记 ChemLab\
├── 合记ChemLab.exe                  Tauri 主程序（Vue 前端 + Rust）
└── resources\
    ├── backend\                     ★ PyInstaller onedir 的 Python 后端
    │   ├── ChemLabBackend.exe         sidecar（16MB）
    │   └── _internal\                 RDKit 等依赖（189MB）
    ├── assets\sops\                 SOP 资源
    └── ...                          （Tauri 自动收集的前端资源）
```

```
┌─ 合记ChemLab.exe（Tauri 主壳）──────────────────┐
│  setup():                                         │
│    1. 初始化工具箱 SQLite                        │
│    2. 定位 sidecar：resources/backend/*.exe       │
│    3. spawn sidecar --port 8765                  │
│       （注入 CHEMLAB_TOKEN / CHEMLAB_PARENT）    │
│    4. 轮询 /api/health 直到就绪                  │
│  run(Exit): 回收子进程                            │
└──────────────────┬───────────────────────────────┘
                   │
                   ▼
┌─ ChemLabBackend.exe（PyInstaller onedir）───────┐
│  _internal/frontend/  ← 合迹前端静态资源（内置） │
│  _internal/  ← RDKit / fastapi / uvicorn …       │
│  日志 → %APPDATA%\ChemLab\logs\backend.log        │
└──────────────────┬───────────────────────────────┘
                   │ 127.0.0.1:8765
                   ▼
              统一 SQLite 库（16 表）
```

## 关键设计

### 1. 选 onedir 而不是 onefile

| | onedir（本方案） | onefile |
| --- | --- | --- |
| 启动速度 | 快（无需解压） | 慢（每次解压到临时目录） |
| 杀软误报 | 低 | **高**（自解压行为是启发式引擎的重点目标） |
| UPX | 不用 | 黄河版用过，是误报重灾区 |
| 体积 | 目录 189MB | 单文件 29MB（需压缩） |

沿用合迹版已验证的结论：**onedir + 不用 UPX**。

### 2. sidecar 定位（Rust 侧）

`backend::find_backend_launcher()` 的回退顺序：

1. 环境变量 `CHEMLAB_PYTHON` —— 显式指定解释器
2. **打包 sidecar** `resources/backend/ChemLabBackend.exe` —— 优先于系统 Python
   （用户机器上可能压根没装 Python）
3. 源码模式 `backend/venv/Scripts/python.exe`
4. 系统 PATH 上的 `python`

抽象成 `BackendLauncher` 枚举，两种方式的差别只在命令行：

```rust
BackendLauncher::Python { exe, script }  → <python> backend/main.py --port N
BackendLauncher::Sidecar { exe }         → <exe> --port N
```

### 3. 打包版没有 stdout —— 日志必须自己落盘

PyInstaller `console=False` 时 `sys.stdout is None`，print 直接抛异常。
所以后端新增 `utils/logging_setup.py`：

- 根 logger 同时写**文件**（`%APPDATA%\ChemLab\logs\backend.log`，UTF-8）与控制台
- uvicorn 的 access/error log 也引到同一文件（否则文件里只有应用日志）
- 打包版没有控制台时自动跳过控制台 handler

这是打包后**唯一能看到"后端到底怎么了"的途径** —— 用户双击应用后窗口空白时，
主壳只能告诉他「后端未就绪」，有了日志才能定位。

### 4. 被主壳拉起时不弹浏览器

原来打包版独立运行时会在就绪后自动 `webbrowser.open()`，端口被占用时也会弹。
现在都加了条件 `is_frozen() and not _is_managed_by_shell()`：

- 独立双击运行 → 照旧弹浏览器（合迹独立版的既有行为）
- 被 Tauri 主壳拉起（`CHEMLAB_PARENT=tauri`）→ **不弹**，主壳里已经有界面了

### 5. 前端静态资源打进 sidecar 而不是 Tauri resources

合迹前端（`frontend-chemeln`）由 PyInstaller 的 `datas` 打进 `_internal/frontend`。
这样 `config.frontend_dir()` 优先找 `frontend` 的逻辑在打包后自然命中，
后端自己就能托管前端（iframe / 子 webview 都从它加载）。

Tauri 侧只带 `assets/sops`（Rust 命令直接读文件，不经过 Python）。

## 构建

```bat
powershell -ExecutionPolicy Bypass -File build\build.ps1 -Fast -Sign
```

五个步骤：

| 步骤 | 动作 | 产物 |
| --- | --- | --- |
| 1 | `pnpm build` | `dist/`（Vue 前端） |
| 2 | `PyInstaller build\ChemLab.spec` | `build\dist\ChemLabBackend\` |
| 3 | 拷贝 sidecar | `src-tauri\resources\backend\` |
| 4 | `npx tauri build` | `src-tauri\target\release\bundle\nsis\*.exe` |
| 5 | `build\sign.ps1` | 签名后的安装包 + `build\ChemLab-CodeSigning.cer` |

> 步骤 2 在 `build/` 目录内执行 —— spec 里的相对路径（`../backend` 等）以此为基准。

### 构建开关

| 开关 | 作用 |
| --- | --- |
| `-Fast` | 关闭 LTO（受限环境用，本机实测快 4 倍） |
| `-SkipSidecar` | 跳过 PyInstaller 步骤（后端没改动时省 2 分钟） |
| `-Sign` | 打包后自动做数字签名 |
| `-TrustLocal` | 签名时顺便把自签名证书加入本机受信任根 |

### 安装界面语言（中文）

`tauri.conf.json` 里配了 `nsis.languages: ["SimpChinese", "English"]`，
同事安装时看到的是中文界面。

**坑：注册表残留会让语言设置被无视。**
NSIS 的 `MUI_LANGDLL_DISPLAY` 宏会优先读注册表里的 `Installer Language` 值，
而不是用配置文件里的默认语言。第一次用英文版装过后，这个值会被写成 `1033`，
之后即使改了配置也依然是英文。

```bat
:: 清掉残留（换语言/重装后如果界面语言不对）
reg delete "HKCU\Software\heji\合记 ChemLab" /v "Installer Language" /f
```

> NSIS 语义：`MUI_LANGUAGE` **第一个是默认语言**，所以 `"SimpChinese"` 要放第一位。
> 同理，若系统界面语言与列表都不匹配，也会回落到第一个。

### 实际安装布局（静默安装后核对）

```
C:\Users\admin\AppData\Local\合记 ChemLab\
├── heji-toolbox.exe        主程序（24MB，debug 构建）
├── resources\
│   └── backend\
│       ├── ChemLabBackend.exe   ← sidecar
│       └── _internal\            （189MB，RDKit 等）
├── _up_\assets\sops\反应类型\   ← SOP 资源
└── uninstall.exe
```

> 注意 sidecar 实际落在 `resources/backend/`，而 Windows 上 `resource_dir()` 返回的是
> **exe 所在目录**（不是 resources 目录）—— 所以定位逻辑要试
> `<资源目录>/resources/backend/` 这个候选。`sidecar_path()` 因此支持多个候选布局。

## 未能在本环境验证的部分

1. **release 构建**：本执行环境里 `lto` 优化阶段会让 rustc 卡死（CPU 几乎不涨）或
   直接崩（`0xc0000005`）—— 与代码无关，是受限环境的进程/内存限制。
   已把 release profile 调成 `lto = "thin"` + `debug = false`（编译更快、体积更小），
   但**完整的 release + NSIS 打包需在正常机器上跑一次**。
   本次产出的安装包用的是 `--debug` 构建，用于验证打包流程与安装后行为。
2. **卸载删文件**：`uninstall.exe /S` 立即返回但不删文件（注册表卸载项正常、
   `InstallLocation` 正确）。本环境的删除操作受沙箱限制（同样现象见
   `rm -rf node_modules` 被拦截），因此**卸载行为需在正常环境确认**。
3. **GUI 表现**：同 P5，Tauri 窗口在本会话无法创建；
   但「主程序拉起 sidecar」「退出时回收 sidecar」这两条已通过进程/端口/日志验证。
4. **杀软误报**：取决于各家的规则，无法代验（见 `docs/杀软误报说明.md`）。

## release 构建提速（已应用）

```toml
[profile.release]
codegen-units = 1
lto = "thin"     # 原为 true：完整 LTO 在本机实测卡死
opt-level = 3
panic = "abort"
strip = false    # 开 strip 时本机 rustc 出现 0xc0000005
debug = false    # 原为 true：发行版不需要调试符号
```

`debug = true` + `strip = false` 的组合会让发布版体积大、编译慢；
关掉后体积与时间都显著改善，且不影响功能。
