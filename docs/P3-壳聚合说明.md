# P3 壳聚合：Tauri 主壳 + Python 子进程管理

> 阶段：P3　｜　状态：已完成　｜　涉及仓库：`D:\DaHan\DaHantd\ChemLab`

## 为什么要做这一步

P0～P2 把「数据」理顺了：三库统一到一套 schema，化学数据合并成 JSON 单一源。
但「进程」还是散的：

| 组件 | 原来的启动方式 | 问题 |
| --- | --- | --- |
| 合成工具箱（Tauri + Vue） | 桌面图标 | 独立进程 |
| 合迹 ChemELN（FastAPI） | 桌面图标 / `launch.py` / 开机自启 | 独立进程，端口占用就静默退出 |
| 黄河 ChemELN（数据源） | — | 数据已并入统一库 |

用户要装两个东西、开两个窗口，而且后端没起时工具箱照常显示——错误只会在用到
实验记录时才暴露。P3 把后端收进主壳：**开应用 → 后端自动就绪；退应用 → 后端自动回收。**

## 关键设计

### 1. 端口策略：先探测，后拉起

`Backend::start()` 的顺序是有讲究的：

```
① 探测 /api/health，且 service == "ChemLab" → 复用已有实例
② 端口被别的服务占着（不是我们的）        → 报错，不拉起
③ 回收本进程上一轮的子进程                 → 防止旧进程占端口
④ 找解释器 → ⑤ 注入令牌 → ⑥ 拉起 → ⑦ 轮询 /api/health
```

- **① 必须先于 ③**：否则「复用」永远命中不了——自己把旧进程杀了，端口就空了。
- **② 是踩过的坑**：旧版 ChemELN 实例也提供 `/api/health`。不校验 `service` 字段
  就会把旧实例当自己的后端复用，结果数据写进了另一个库。
- **③ 必须在 ① 之后**：见上。

### 2. 令牌：主壳生成，注入环境变量

主壳用 `CHEMLAB_TOKEN` 环境变量把令牌传给后端（`backend/config.py` 的
`TOKEN_ENV_VAR`），后端 `utils/security.py` 优先读环境变量。

于是：主壳知道令牌 → 通过 `backend_status` 命令交给前端 → 前端带
`X-ChemLab-Token` 头请求后端。**三方共享同一个令牌，中间不落盘、不走明文接口**。

复用已有实例时，令牌从 `/api/session`（免鉴权路径）取——那是那个实例自己的令牌。

### 3. 令牌头改名但兼容旧名

产品从 ChemELN 改名为 ChemLab，令牌头同步改为 `X-ChemLab-Token`，
但**旧名 `X-ChemELN-Token` 仍然接受**（合迹前端与已打开的浏览器标签页还在用）。
Cookie 同理，新旧两个名字都下发一份。

### 4. Python 解释器发现（多级回退）

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 环境变量 `CHEMLAB_PYTHON` | 显式指定 |
| 2 | `backend/venv/Scripts/python.exe` | 仓库内标准位置 |
| 3 | 同目录 sidecar `chemlab-backend.exe` | 打包模式（P6 启用） |
| 4 | PATH 上的 `python` / `python3` | 最后兜底 |

端口可用环境变量 `CHEMLAB_PORT` 覆盖（默认 8765）。

### 5. 零新增依赖

健康检查用 `std::net::TcpStream` 手写最小 HTTP/1.0 请求——为了探活拖进
`reqwest`（一整套 TLS 栈）不划算。HTTP/1.0 的好处是服务端响应后直接关连接，
不会分块，省掉 chunked 解码（仍保留了 `dechunk` 兜底）。

### 6. 退出即回收

- `RunEvent::Exit` → `Backend::stop()` → `kill()` + `wait()`
- `impl Drop for Backend` 兜底：即使退出钩子没跑到，也不会留下占端口的孤儿
- **只杀本进程拉起的子进程**：复用的已有实例不动（可能是用户手动开的服务）

## 用法

### 准备后端环境（一次性）

```bat
cd ChemLab\backend
python -m venv venv
venv\Scripts\pip install -r requirements.txt
```

### 日常开发

```bat
cd ChemLab
pnpm tauri dev
```

主壳会自动拉起后端。改了 Python 代码后，在「我的 → 后端服务」点「重启后端」即可，
不用整个退出应用。

### 单独调后端

```bat
cd ChemLab\backend
venv\Scripts\python main.py --port 8765
```

## 验证

```bat
cd src-tauri
cargo check                              # 类型检查
cargo test --lib                         # 单元测试（2 个：令牌长度、chunked 解码）
cargo test --lib -- --ignored            # 集成测试：真拉起后端 → 复用 → 停止释放端口
```

集成测试会真的启动 Python 后端（端口 8798），验证三件事：

1. 首次 `start()` 能把后端拉起来并拿到令牌
2. 第二次 `start()` 命中「复用」而不是拉第二个
3. `stop()` 之后端口释放（不留孤儿进程）

## 已知限制

- 打包模式（release）下 `backend/` 随 sidecar 分发，尚未实现（P6）
- 后端代码改动后复用旧实例不会自动重启——需手动点「重启后端」
- 主壳被任务管理器强杀时，子进程可能残留（Windows 无父进程自动清理机制）；
  下次启动会复用该实例，不会重复拉起
