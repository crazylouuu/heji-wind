# P5 深度集成：原生子 webview + iframe 降级

> 阶段：P5　｜　状态：已完成（子 webview 通道可选启用，默认 iframe 兜底）
> 依据：`docs/三应用整合方案.md` 4.7 节「子 webview 嵌入方案（已实测）」

## 目标

P4 把实验记录页用 iframe 嵌进了主壳。能用，但有 iframe 固有的问题：
边框/滚动条、跨源限制、需要 postMessage 绕圈子。

P5 按方案升级为 **Tauri 原生子 webview**（同一桌面窗口内的原生 webview 控件），
同时保留 iframe 作为降级路径。

## 两条通道

| 通道 | 说明 | 状态 |
| --- | --- | --- |
| **child** | `Window::add_child` 创建原生子 webview，加载 `http://127.0.0.1:8765/` | 已实现，`--features lab-child-webview` 启用 |
| **iframe** | 主 webview 内的 `<iframe>`，postMessage 桥 | 已实现，**默认兜底**，P4 已验证 |

前端 `LabView.vue` 自动选择：

```
进入 /lab
  ├─ 在 Tauri 里？──否──→ iframe 通道
  │      │是
  │   invoke("lab_open")  ──失败──→ iframe 通道
  │      │成功
  │   invoke("lab_place")  放置子 webview 到内容区矩形
  │   轮询 invoke("lab_poll") 直到 ready（最多 8 秒）
  │      │超时──→ 退回 iframe 通道
  │   ready → 分段器改走 invoke("lab_nav")
```

## 通信拓扑

```
┌─ Tauri 主进程（Rust）──────────────────────────────┐
│  lab.rs：子 webview 生命周期 / 位置 / eval 注入      │
└──────┬──────────────────────────────┬─────────────┘
       │ eval("window.__chemlabNav('x')") │ GET /api/lab/events
       ▼                                  ▼
┌─ 子 webview（合迹前端 127.0.0.1:8765）─┐   ┌─ Python 后端 ─┐
│  app.js 暴露 window.__chemlabNav(view)  │   │  routers/lab.py│
│  加载完成 → POST /api/lab/events ready  │   │  事件环形缓冲  │
│  现有 fetch('/api/...') 天然同源         │   └───────────────┘
└──────────────────────────────────────────┘
```

**为什么绕一圈走后端**：子 webview 是远程 origin，有两个硬限制——

1. `is_local_url()` 只认 `tauri://` 或 devUrl 相对路径 → 远程 origin 调不了 Tauri IPC
2. `on_page_load` 对子 webview **触发不可靠**（实测有时触发有时不触发，且与页面真实加载状态不同步）

于是让**子页主动向后端报 ready**，主壳轮询后端得知 —— 不依赖 IPC，也不依赖 on_page_load。
主壳→子页则用 `eval()` 注入（方案实测 12/12 成功）。

## 三个新增/沿用的实测约束

| # | 约束 | 应对 |
| --- | --- | --- |
| 1 | `add_child` / `WebviewBuilder` 需要 tauri 的 `unstable` feature | 收敛到 `lab-child-webview` Cargo feature（默认开启，可 `--no-default-features` 退回） |
| 2 | `add_child` 定义在 `Window` 上，不是 `WebviewWindow` | 用 `app.get_window("main")` |
| 3 | Windows 上在同步命令里调 `add_child` 会死锁 | 创建动作放独立线程（`std::thread::spawn`），命令立即返回，前端轮询状态 |
| 4 | **（本次新发现）二进制里只要链接了 `tauri::Webview`，就会拉进 WebView2 的 COM 依赖** | 见下 |

### 第 4 条的坑（值得单独记）

把 `Webview` 放进状态结构（`Option<Webview>`）后：

- 应用 exe 正常（能启动、能拉起后端）
- **`cargo test` 生成的测试进程直接起不来**：`STATUS_ENTRYPOINT_NOT_FOUND`（0xc0000139）

原因：字段类型会生成 drop glue，把 `Webview` 的析构链（以及 WebView2 COM 依赖）链进来；
测试宿主进程初始化 COM 时失败。应用进程有自己的 COM 初始化路径，所以不受影响。

解决：**feature + `not(test)` 双门控**。

```rust
// 应用构建（含 feature）→ 真正的 Webview
#[cfg(all(feature = "lab-child-webview", not(test)))]
type ChildWebview = tauri::Webview;
// 测试构建 / 未启用 feature → 占位类型，不链 COM 依赖
#[cfg(any(not(feature = "lab-child-webview"), test))]
type ChildWebview = ();
```

所有调用 Webview 方法的代码（`set_position` / `set_size` / `eval` / `close`）也一并门控。
结果：应用构建有原生子 webview 能力，`cargo test` 正常（5 个测试全过）。

## 后端事件中转（`backend/routers/lab.py`）

- `POST /api/lab/events` —— 子页上报事件（`{"event":"ready"}`）
- `GET /api/lab/events?since=N` —— 主壳拉增量
- `GET /api/lab/reset` —— 重置

进程内内存环形缓冲（50 条），只存事件不存数据。
在鉴权保护之下（`/api/` 前缀，需要会话令牌），实测：上报 200 / 拉取返回事件 / 无令牌 401。

## 顺带修的两个真问题

**1. 端口上的后端可能是旧代码**
主壳复用已在运行的后端实例时，之前只校验 `service == "ChemLab"`。现在 `/api/health`
多返回一个 `disk_fingerprint`（磁盘现算），主壳比对 `code_fingerprint`：
- 不一致且是自家进程 → 直接重启（改了 Python 代码却用旧进程，这类问题极难自查）
- 不一致且是外部实例 → 复用但提示「请在设置里重启后端」

**2. 浏览器模式下状态条说谎**
原来非 Tauri 环境下 `getBackendStatus` 直接返回 `running: true`，
结果后端没起时状态条仍显示「已连接」，而 iframe 里是一片「无法访问此网站」。
现在浏览器模式会真的 `fetch /api/health` 探测。

## 启用方式

```bat
:: 默认（已含子 webview 通道）
cargo build

:: 强制退回纯 iframe（不链接 tauri unstable）
cargo build --no-default-features

:: 明确启用子 webview
cargo build --features lab-child-webview
```

前端无需改动：命令不存在或返回错误时会自动降级到 iframe。

### 未能在本环境验证的部分

**GUI 实机验证受阻**：本次开发所在的执行会话里，Tauri 进程能启动（后端被正常拉起），
但**窗口从未被创建**（枚举全部可见/不可见窗口都找不到 heji-toolbox）。
因此以下三点只能由用户在正常桌面会话中确认：

1. 子 webview 是否真的显示在内容区（位置与尺寸是否贴合）
2. 温和退出应用时子 webview 是否随主窗口一起回收
3. 顶部导航切换到其它页面时子 webview 是否正确隐藏

功能层面已通过 mock invoke 验证了前端调用序列，Rust 侧逻辑有单元测试覆盖；
**建议用户在自己的桌面上跑一次 `pnpm tauri dev` 进入「实验记录」页确认**。

## 已知限制

- 子 webview 通道依赖 tauri unstable API，升级大版本时需复核
- 主壳被强杀时子 webview 可能残留（Windows 无父进程自动清理）
- 子页→主壳目前只有「ready」一个上行事件；更细的交互事件需扩展后端事件协议
